| Decision | Choice |
|---|---|

## 1. Bubble substrate: second vello Scene → own texture → screen-space composite

### 1.1 Why not the alternatives

- **Append into the terminal scene** (as viz underlays do at src/direct_render.rs:252-254): rejected. The terminal texture is mapped onto the warping/rotating plane in Plane3d/Mobius3d (src/scene/mod.rs:390-402; vertex warp src/systems.rs:2407-2449) — anything drawn there moves with the plane, violating "stays FIXED through terminal scrolling and camera movement". Also the terminal texture is grid-sized, not window-sized (src/terminal.rs:220-225), while HUD anchors are window-relative.
- **CPU rasterize with swash + `Image` upload** (like the back-plane debug image, src/rendering.rs:17-46): rejected. We'd own glyph rasterization, blending, and per-frame full-texture uploads; worse AA than vello's path rendering; only "advantage" is avoiding a second GPU pass we get nearly free.
- **bevy_text/bevy_ui**: see §3 — rejected on binary/wasm size, second text stack, and visual mismatch.
- **Parenting HUD to `TerminalPlaneCamera`**: rejected; ortho `scale = zoom` (src/scene/mod.rs:609-617) would resize the HUD with RGP zoom commands.

### 1.2 Chosen pipeline (every ingredient proven in-repo)

1. **Texture pair**: reuse `new_terminal_render_image` / `new_terminal_image` (pub(crate), src/direct_render.rs:160-212) to create an `avatar` render texture (Rgba8Unorm storage — vello requires a non-sRGB storage target, src/direct_render.rs:188-196) and present texture (sRGB view, nearest sampler). Sized to the **window physical framebuffer** (`Window::resolution.physical_size()`, cf. src/terminal.rs:342-356). While the avatar is hidden and no utterance is live, both are resized to 1×1 and the quad is `Visibility::Hidden` — zero steady-state cost. At 2560×1440 the live pair costs ≈29 MB VRAM; accepted (the terminal already pays an equivalent pair), and it buys identity presentation and window-space drawing with no sprite math.
2. **Scene exchange**: a second exchange with the exact `DirectTerminalSceneExchange` shape — pending-frame mutex + recycled-`Scene` mutex (src/direct_render.rs:69-146). Lives in `src/direct_render.rs` beside the terminal one so `DirectTerminalRenderState` stays private.
3. **Render**: a second render-world system in `RenderGraphSystems::Begin`, ordered `.after(render_terminal_frame)`, reusing the **same** `GpuRenderer` resource (src/direct_render.rs:87-98, 319-323). `GpuRenderer::render_scene_to_texture_view(device, queue, view, w, h, base_color, scene)` takes an arbitrary scene/view/size (verified: REG/parley_ratatui-0.3.4/src/renderer.rs:187-211 → `vello::Renderer::render_to_texture`, REG/vello-0.9.0/src/lib.rs:474) — two calls per frame on one renderer is a plain sequential submission. Base color: `PenikoColor::TRANSPARENT`. Then the same render→present `copy_texture_to_texture` (src/direct_render.rs:342-354) and the same size-mismatch frame-retention guard (src/direct_render.rs:299-317).
4. **Present**: reuse `TerminalPresentMaterial` + `fullscreen_quad()` verbatim (both already `pub`, src/present.rs:31, 68-79). The shader's centering math (src/shaders/terminal_present.wgsl:34-45) degenerates to the **identity** when texture size == viewport size, which the avatar texture guarantees — crisp `textureLoad` per physical pixel, zero new shader/material code. Spawn mirrors the terminal quad (src/scene/mod.rs:371-380): `Mesh2d` + `MeshMaterial2d` + `NoFrustumCulling` + `RenderLayers::layer(2)` + marker `AvatarOverlayQuad`.
5. **Composite**: dedicated `AvatarBubbleCamera` — `Camera2d`, `order: 5`, `ClearColorConfig::None`, `RenderLayers::layer(2)`, `Msaa::Off` — the `AiEffectCamera` recipe (src/effects.rs:341-354). Camera order stack becomes: 0 flat-2D → 1 terminal 3D → **5 bubble** → **6 mascot** → 10 effects wash. Bubble *before* mascot so the vello glow disc drawn in the overlay texture sits **under** the mascot (placement math keeps bubble text and mascot rects disjoint); the mood wash at order 10 tints the avatar like everything else — consistent with the effects organ's "whole surface" contract (src/effects.rs:1-11).

**Blend-mode verification gate**: the material's `ALPHA_BLENDING` specialization (src/present.rs:53-57) is correct for the terminal's mostly-opaque output; over a fully transparent base the vello output's alpha treatment must be eyeballed for fringing on glow gradients. If fringing appears, the fix is a one-line `PREMULTIPLIED_ALPHA_BLENDING` variant material (subclassing the specialize fn), not a redesign.

### 1.3 Required edits to existing camera/material plumbing

- **src/scene/mod.rs:252-261** — `PresentationParams.camera_2d` filter currently `(With<Camera2d>, Without<TerminalPlaneCamera>, Without<AiEffectCamera>)` and deactivates matches in 3D modes (src/scene/mod.rs:570-575). Add `Without<crate::avatar::AvatarBubbleCamera>` or the bubble dies in 3D modes. The mascot camera is safe from `camera_3d` (filter is `With<TerminalPlaneCamera>`, src/scene/mod.rs:262) and from the presentation pose writer (src/scene/mod.rs:609-626, same filter via `PlaneCameraQuery`).
- **src/systems.rs:472** — `sync_terminal_materials`' `present_query` matches **all** `MeshMaterial2d<TerminalPresentMaterial>` and rewrites their texture to the terminal image on every dirty frame (src/systems.rs:500-506) — it would clobber the avatar quad. Add `With<TerminalSprite>` to that query (the terminal quad carries it, src/scene/mod.rs:372); the avatar organ owns an equivalent rebind system for its quad (same stale-bind-group rationale as src/systems.rs:494-499).

## 2. Real text: direct parley vs bevy_text/bevy_ui — honest comparison

| | direct `parley 0.10` + vello (chosen) | enable `bevy_ui`(+`bevy_text`) |
|---|---|---|
| New compiled code | **None** — parley 0.10.0 already compiled for parley_ratatui (Cargo.lock: parley 0.10.0's sole user is parley_ratatui; verified `cargo tree --locked --offline` per fact sheet §4) | bevy_text + bevy_ui + bevy_ui_render + taffy + a *second* parley (0.9.0, in-lock for bevy_text) + glyph-atlas pipeline; native binary and **wasm bundle** both grow (wasm size is a first-class product goal, Cargo.toml:139-143) |
| Rendering | Same vello compute rasterizer and Msaa8 AA as the terminal glyphs (REG/parley_ratatui-0.3.4/src/renderer.rs:122-127) — bubble text is visually identical in weight/AA to terminal text | Separate glyph-atlas raster + sampling; visibly different AA/hinting from the vello-drawn terminal |
| Bubble chrome | Rounded rect + tail + accent border are native vello paths in the same scene | Rounded corners via UI border-radius, but the tail needs image assets or a custom node |
| Typewriter | Cluster-exact reveal from one cached layout (§8) | Would re-set the `Text` string per frame (re-shape per frame) or hack alpha spans |
| Camera integration | One overlay camera, a pattern the repo already ships twice (src/effects.rs:340-365) | UI render-graph targets a camera; interacts with the curated three-camera set and the mode-driven activation toggling (src/scene/mod.rs:566-584) in ways this repo has never exercised |
| Cost of choice | ~350–450 lines of owned plumbing (contexts, wrap, reveal, draw) — mitigated by the canonical in-tree conversion `paint_layout` (REG/parley_ratatui-0.3.4/src/renderer.rs:982-1024) and parley's re-paint-from-cached-layout being that crate's own steady-state pattern (text.rs:453, 481-488) | Less text-plumbing code, but new dependency surface to a deliberately curated feature list (Cargo.toml:46-65) |

**Recommendation: direct parley.** The one honest advantage of bevy_ui (less code we own) is outweighed on every axis this project has declared: minimal dependency surface, wasm bundle size, single rendering stack, and visual coherence with the vello terminal.

Type unification making this work with zero conversion: `parley::Run::font() -> &FontData` is the same `linebender_resource_handle 0.1.1` `FontData` that `vello::Scene::draw_glyphs` consumes (REG/parley-0.10.0/src/lib.rs:131; REG/peniko-0.6.1/src/lib.rs:43; one `linebender_resource_handle` in Cargo.lock). `parley_ratatui::vello::{Scene, Glyph, peniko}` are already reachable and used by ratty (src/viz_draw.rs:30-32; whole-crate re-export REG/parley_ratatui-0.3.4/src/lib.rs:26).

The 5×7 stroke font in `src/viz_draw.rs` is untouched — it remains the chart-label substrate (its module comment even predicts this design: labels exist *because* "parley_ratatui exposes no arbitrary-text API into the scene", src/viz_draw.rs:23-27). The avatar substrate keeps its conventions where they apply: append-time truncation against a pixel-known budget, a minimum-legible-size drop, explicit alignment anchors (src/viz_draw.rs:965-1024) — but with real wrapping instead of truncate-only.

## 3. Font sourcing

New file **`src/fonts.rs`**:

```rust
//! Embedded DejaVu Sans Mono, shared by the wasm terminal fallback and the
//! avatar bubble substrate. One copy of the bytes per face, both targets.
pub(crate) const EMBEDDED_MONO_REGULAR: &[u8] =
    include_bytes!("../assets/fonts/DejaVuSansMono.ttf");
pub(crate) const EMBEDDED_MONO_BOLD: &[u8] =
    include_bytes!("../assets/fonts/DejaVuSansMono-Bold.ttf");
```

- `src/terminal.rs:369-372` currently wasm-gates identical `include_bytes!`; repoint those uses at `crate::fonts::*` so the blob exists once.
- The avatar's own `FontContext` registers these via `fontique::Collection::register_fonts` (REG/fontique-0.10.0/src/collection/mod.rs:202) with a `FontInfoOverride` family name (`"ratty-avatar-mono"`), exactly as parley_ratatui does for bundled fonts (REG/parley_ratatui-0.3.4/src/text.rs:960-971). Zero-copy `Blob::from_static`.
- **Why embed rather than resolve the configured system family** (src/config.rs:281-292 default "DejaVu Sans Mono"): determinism and wasm parity. System discovery can miss the family natively; wasm has no system fonts at all (src/terminal.rs:365-368). Embedding gives the identical face on both targets — the same reasoning the terminal already applies on wasm. Cost: ~680 KB native binary growth (both faces); wasm bundle unchanged (already embeds them). A separate `Blob` from the terminal renderer's copy means a separate vello glyph-cache font identity — cache duplication only, not correctness (fact sheet §1).
- Mixed-case prose in a mono face satisfies the goal's "real prose: mixed case, punctuation — not an uppercase-only stroke font" clause. A proportional face is a later drop-in (one more embedded blob), not needed by the goal text.

## 4. Mascot: screen-fixed glTF at the HUD anchor

### 4.1 Camera and layers

Spawned in `AvatarPlugin`'s startup system (pattern: src/effects.rs:341-365, src/scene/mod.rs:315-330):

```rust
commands.spawn((
    AvatarMascotCamera,
    Camera3d::default(),
    Camera { order: 6, clear_color: ClearColorConfig::None, ..default() },
    Projection::Orthographic(OrthographicProjection {
        near: -2000.0, far: 2000.0, ..OrthographicProjection::default_3d()
    }),
    Transform::from_xyz(0.0, 0.0, 800.0).looking_at(Vec3::ZERO, Vec3::Y),
    RenderLayers::layer(AVATAR_MASCOT_LAYER),   // 3
    Msaa::Off,
));
commands.spawn((
    DirectionalLight { illuminance: 15_000.0, shadow_maps_enabled: false, ..default() },
    Transform::from_rotation(Quat::from_euler(EulerRot::ZYX, 0.0, -0.9, -0.45)),
    RenderLayers::layer(AVATAR_MASCOT_LAYER),
));
```

This camera is **never** written by RGP `c`-verb machinery: `apply_rgp_stage`/`apply_terminal_presentation` only move `TerminalPlaneCamera` (src/systems.rs:2488-2581; src/scene/mod.rs:609-626, filter at :262). Fixed pose + fixed ortho scale 1.0 ⇒ world units are logical pixels, screen-aligned, in every presentation mode — the mascot cannot move with yaw/pitch/zoom/warp/Möbius by construction. Scene lights are on layer 0 (src/scene/mod.rs:422-447), hence the dedicated layer-3 light.

**Layer propagation**: glTF scenes spawn descendants on default layer 0, invisible to a layer-3 camera. New system `propagate_avatar_layer` — the `apply_instance_brightness` upward-walk pattern verbatim (src/systems.rs:1582-1639): query `(Entity, &ChildOf), (With<Mesh3d>, Without<AvatarLayerTagged>)`, walk `ChildOf` to find `AvatarMascotRoot`, insert `RenderLayers::layer(3)` + `AvatarLayerTagged`.

### 4.2 Curated embedded glTF with wasm parity (#12)

Today wire glTF is native-only because runtime bytes must be staged to a filesystem path for the `AssetServer` (src/model.rs:345-352; loadability gate src/model.rs:299-302). The mascot is different: it is a **compile-time curated asset**, so it can ride Bevy's `embedded://` asset source, which is a memory reader with no filesystem — target-independent:

- `AssetPlugin` (in `DefaultPlugins`, added before `TerminalPlugin` on both targets — src/main.rs:74-106, src/web.rs:347-375) registers the `embedded` source and inserts `EmbeddedAssetRegistry` (REG/bevy_asset-0.19.0/src/lib.rs:352-362, 413); the registry's `Dir` is shared with the reader, so inserts from a later plugin are visible (REG/bevy_asset-0.19.0/src/io/embedded/mod.rs:26-45, 92-115).
- `AvatarPlugin::build` inserts the mascot bytes **from the existing `EmbeddedObjects` rust-embed registry** (src/model.rs:18-19, folder `assets/objects/`) so the binary holds one copy:

```rust
let bytes = crate::model::embedded_object_bytes(spec.registry_name)?; // thin accessor over EmbeddedObjects::get
app.world().resource::<bevy::asset::io::embedded::EmbeddedAssetRegistry>()
    .insert_asset(std::path::PathBuf::new(),
                  std::path::Path::new("ratty/avatar/SpinyMouse.glb"),
                  bytes); // &'static [u8] in release; Vec<u8> in debug (rust-embed reads disk)
```

- Spawn: `commands.spawn((AvatarMascotRoot, Transform..., Visibility..., RenderLayers::layer(3), WorldAssetRoot(asset_server.load(GltfAssetLabel::Scene(0).from_asset("embedded://ratty/avatar/SpinyMouse.glb")))))` — the exact RGP/cursor glTF spawn shape (src/systems.rs:1110-1116; src/model.rs:211-218). `WorldAssetRoot` is Bevy 0.19's rename of `SceneRoot` (REG/bevy_world_serialization-0.19.0/src/components.rs:12-23). `bevy_gltf` is compiled on both targets (shared feature list, Cargo.toml:51).

**Registry (#12)**: mascot names are a closed compile-time table — never paths, never payload bytes:

```rust
pub struct AvatarModelSpec {
    /// Immutable wire id — the embedded object file name (#12).
    pub registry_name: &'static str,
    /// The embedded:// URL the AssetServer loads.
    pub embedded_url: &'static str,
    /// Uniform scale calibrating model units to AVATAR_BASE_SIZE_PX height.
    pub root_scale: f32,
}
pub const AVATAR_MODELS: &[AvatarModelSpec] = &[AvatarModelSpec {
    registry_name: "SpinyMouse.glb",
    embedded_url: "embedded://ratty/avatar/SpinyMouse.glb",
    root_scale: /* calibrated at integration */,
}];
```

M3 curates exactly one entry. `SpinyMouse.glb` (1.6 MB, already shipped in `assets/objects/`) is the placeholder choice — the rat mascot; swapping the curated model is a one-line table change (`Ferris.glb`, 9 KB, is the low-fat alternative if bundle weight matters more than theme). Unknown names reject `bad-asset` (code exists, src/query.rs:90). The command surface stays semantic — a later skinned/TTS milestone replaces the spec table and spawn path behind unchanged `avatar.*` verbs.

**Risk + gate**: this is the repo's first `embedded://` load and first wasm glTF. The mechanism is verified in vendored source (above), but the milestone's CI/manual gate must include a site-build check that the mascot appears. If a genuine wasm blocker surfaces, the honest fallback (per the locked constraints) is: `avatar.set` rejects `unsupported` **on wasm only**, with the bubble substrate fully functional there (speaker identification lives in the bubble, §6) — an explicitly reported deferral, not a silent degrade.

### 4.3 Anchor math, choreography, glow

Anchor → world position for the mascot camera (world = logical px, origin center, +y up — same convention as `cursor_pose`, src/systems.rs:2748-2751):

```
(w, h) = Window::resolution.size()            // logical
(nx, ny) = anchor.normalized()                // {0, .5, 1}² over the nine anchors, y down
inset    = AVATAR_MARGIN_PX + half_extent(scale), applied toward window center per axis
px = nx*w ∓ inset + offset.x ;  py = ny*h ∓ inset + offset.y     // window space, y down
world = Vec3::new(px - w/2.0, h/2.0 - py, AVATAR_MASCOT_DEPTH)   // depth 10.0, cf. CURSOR_DEPTH src/config.rs:28
```

Reads `Window` directly each frame (window-relative, not grid-relative — `TerminalViewport` is the *grid* logical size, src/scene/mod.rs:66-73, which underfills the window by the cell remainder), so it self-corrects on resize with no dedicated hook, like `inline_layout` does per frame (src/systems.rs:784-810).

**Choreographies** (`bob`, `tilt`, `lean`, `nod`, `spin`) are named **root-transform** programs applied by `animate_avatar_mascot` to `AvatarMascotRoot` — the cursor's spin/bob math generalized (src/systems.rs:2752-2763): a persistent subtle idle bob (presence furniture), plus one-shot gestures (~1.2 s envelopes): tilt = ±0.18 rad z-sway; lean = eased z-lean toward the bubble side and back; nod = two x-rotation dips; spin = one full y-turn. No glTF animation clips in M3 (`gltf_animation` stays available for the later skinned milestone).

**Speaking-duration presence glow**: a vello radial-gradient disc appended into the overlay scene behind the mascot's window rect, alpha driven by the utterance envelope — ramp-in over 250 ms at `avatar.speak` commit, gentle 1.2 Hz pulse while revealing and holding, 400 ms fade at expiry. Because the bubble camera (order 5) composites before the mascot camera (order 6), the glow sits **behind** the mascot, and the utterance drives exactly its duration.

## 5. Wire grammar (OSC 777 `ratty:` family — no RGP/APC change; RGP is the separate `ESC _ ratty;g;` channel, src/rgp.rs:6, protocols/graphics.md)

Payload rules unchanged: `k=v&k=v`, values percent-encoded (src/osc.rs:12, 1018-1077). Malformed commands with `tok=` still get envelope-level error acks (token extracted before command parse, src/osc.rs:641-653, 690-707).

```
ratty:avatar.set[;model=<registry-name>][&position=<anchor>][&dx=<px>][&dy=<px>][&scale=<f32>][&tok=...]
ratty:avatar.gesture;gesture=bob|tilt|lean|nod|spin[&tok=...]
ratty:avatar.speak;text=<pct ≤1000 bytes>&from=<pct ≤64 bytes>[&color=#rrggbb][&rate=<chars/s>][&hold=<secs>][&tok=...]
ratty:avatar.hide[;tok=...]
```

- `position` vocabulary (nine anchors): `top-left top top-right left center right bottom-left bottom bottom-right`. **State default `bottom-right`** per the locked goal — moved out of the parser (which today hardcodes `"top-right"`, src/osc.rs:876) into `AvatarState::default()`, so `avatar.set;model=…` alone lands at the goal's default.
- `avatar.set` becomes **partial-update** semantics (all keys optional), matching `cursor` (src/osc.rs:740-747, apply at src/ai.rs:550-605). First `avatar.set` with no `model` uses `AVATAR_MODELS[0]`. Atomicity rule copied from `cursor` (src/ai.rs:558-576): any invalid field rejects the whole command.
- `dx`/`dy`: logical px, **+y down** (viz/window convention), clamped to `±AVATAR_OFFSET_MAX_PX` (512). `scale` clamped `0.25..=4.0`; `rate` clamped `5.0..=200.0` (default 40); `hold` clamped `0.0..=30.0` (default 4). Clamp-to-documented-bounds is the sound organ's established wire semantics ("the wire requests, it never owns the mixer", src/osc.rs:407-409) — the ack still commits; the bound implements the goal's "bounded pixel offset".
- Hard rejects (never clamped): `text` > 1000 UTF-8 bytes → `too-large`; `from` missing → parse failure (required key) / `from` > 64 bytes → `too-large`; unknown `position` → `bad-anchor` (new code); unknown `gesture` → `bad-gesture` (new code); unknown `model` → `bad-asset`; `avatar.speak`/`avatar.gesture` with no avatar shown → `nothing-active` (code exists, src/query.rs:131). New codes are append-only consts in `src/query.rs` `codes` (src/query.rs:57-135).

### 6.1 `src/avatar/mod.rs`

```rust
//! The avatar organ (#23, M3.10): a screen-fixed presence mascot and a
//! real-text speech bubble, composited over every presentation mode.
//!
//! Honest limitations: one avatar, one utterance at a time (a new
//! `avatar.speak` preempts the current one — attribution keeps handoff
//! legible); bubble text that cannot fit the window height is trimmed by
//! whole trailing lines with a visible overflow marker, and the full text
//! stays queryable via `state.scene`.

pub const AVATAR_BUBBLE_LAYER: usize = 2;
pub const AVATAR_MASCOT_LAYER: usize = 3;
pub const MAX_AVATAR_TEXT_BYTES: usize = 1000;
pub const MAX_AVATAR_SPEAKER_BYTES: usize = 64;
pub const AVATAR_OFFSET_MAX_PX: f32 = 512.0;
pub const AVATAR_SCALE_MIN: f32 = 0.25;
```

```rust
for line in body.lines() {
  for item in line.items() {
    let PositionedLayoutItem::GlyphRun(run) = item else { continue };
    let r = run.run();
    let mut x = run.offset();
    let y = run.baseline();
    scene.draw_glyphs(r.font())
      .brush(&brush).hint(false)
      .transform(Affine::translate((origin.x as f64, origin.y as f64)))
      .font_size(r.font_size())
      .normalized_coords(r.normalized_coords())
      .draw(Fill::NonZero, r.visual_clusters().flat_map(|cluster| {
          let revealed = cluster.text_range().end <= revealed_bytes;
          let glyphs: Vec<vello::Glyph> = revealed.then(|| cluster.glyphs().map(|g| {
              let gx = x + g.x; let gy = y - g.y;      // y negation per renderer.rs:1015
              vello::Glyph { id: g.id as u32, x: gx, y: gy }
          }).collect()).unwrap_or_default();
          x += cluster.advance();                       // advance even when hidden
          glyphs
      }));
  }
```

## 8. Typewriter mechanics (spec)

1. **Commit** (`apply_avatar_commands`): validate → `AvatarUtterance = Some(Utterance { started: now, revealed_bytes: 0, .. })`, ack commit. A live utterance is **replaced** (preemption is the M3 policy; the attribution chip makes agent handoff legible; queuing is a non-goal until a real need shows).
2. **Advance** (`advance_avatar_utterance`): target chars = `rate * (now - started)`; walk `char_indices` forward from the current offset to the target count (O(new chars), monotonic). At `revealed_bytes == text.len()` set `done_at`; at `now > done_at + hold` clear the utterance (final publish erases the bubble; glow fades over the last 400 ms of hold).
3. **Layout once, reveal many**: layouts are cached by `(text_hash, wrap_px, font_px)`; the reveal only changes which clusters emit glyphs during the per-frame scene re-encode — vello scenes are rebuilt every publish anyway (`Scene` recycle-reset, src/direct_render.rs:113-124), so partial emission costs nothing extra. This is parley_ratatui's own steady-state pattern (Arc-cached layouts re-painted every build, REG/parley_ratatui-0.3.4/src/text.rs:453, 481-488).
4. **Cluster correctness**: reveal is decided per **cluster** by logical `text_range().end <= revealed_bytes`, painted in **visual** order with advances accumulated for hidden clusters (§6.2 loop). Consequences: ligatures never half-draw (continuation clusters share the start's range, REG/parley-0.10.0/src/layout/cluster.rs:168-175); RTL runs reveal in logical (reading) order at their correct visual positions; combining marks reveal atomically with their base.
5. **Reveal survives re-layout**: progress is a byte offset into the text, not a glyph count, so a window resize/DPI change mid-utterance re-wraps and the reveal continues seamlessly.
6. **Caret**: optional accent block at the last revealed cluster's caret x (`cluster.advance()` running sum) while revealing — free from the same walk.
7. **Publish policy**: `sync_avatar_overlay` publishes when `AvatarOverlayDirty` is set OR an utterance is live (glow/typewriter animate per frame) OR the texture was resized; hidden+idle publishes once (clearing frame) then goes silent with 1×1 textures.

**Bubble geometry**: `wrap_px = clamp(0.42 * window_physical_w, 240, 560) * scale * render_scale`; `font_px = AVATAR_FONT_LOGICAL_PX * scale * render_scale` (shaped at physical px with `quantize=true` — crisp at every DPI, REG/parley-0.10.0/src/context.rs:70-72,87-108). Bubble anchors adjacent to the mascot toward the window center (above it for `bottom*`/`center` anchors), tail pointing at the mascot center, clamped inside the window with an 8 px margin. 1000 bytes at defaults ≈ 20 wrapped lines ≈ 420 px — fits any sane window; smaller windows trim trailing whole lines with a visible `⋯ +N lines` marker row (explicit, mirrored by full text in `state.scene`; the viz_draw truncate-at-append convention, src/viz_draw.rs:975-986, upgraded from silent-truncate to marked-truncate).

## 9. Governance: #16 / #12 / #21 / acks

- **#16 (macros)**: `avatar.set` and `avatar.hide` mutate a scene-global singleton (exactly the mode/warp class) → added to `is_scene_global` (src/osc.rs:633-638), so a recording containing them classifies **privileged** at capture (src/macros.rs:498-500) and needs the exclusive scene lock to play. `avatar.speak`/`avatar.gesture` are ephemeral self-expiring choreography (the flash/pulse class) → recordable, non-privileged.
- **#21 (reactive)**: **no** avatar command is added to `is_rule_safe_action` (src/osc.rs:614-627 unchanged) — so rules cannot fire avatar commands directly, and any macro containing one is not rule-safe (finalize predicate, src/macros.rs:343-346, 501-502), so `macro.play` rules can't smuggle them either (checked at rule.set and fire, src/reactive.rs:454-487). Justification: `avatar.speak` preempts another agent's live utterance (cross-agent blast radius) and `avatar.set/hide` are scene-global; the allowlist's charter is "no spawn/remove/re-anchor blast radius" (src/osc.rs:604-613). Reactive speech is a possible later, deliberate amendment — not a default.
- **#12 (immutable registry IDs)**: mascot models resolve exclusively against the compile-time `AVATAR_MODELS` table over ratty-embedded bytes; never a filesystem path, never payload bytes (§4.2). Same posture as `object.add`/`cursor` (src/ai.rs:12-15; src/model.rs:305-316).
- **Origin**: nothing special — the recorder tap already skips `CommandOrigin::Rule` fire noise (src/ai.rs:56-63), and avatar commands are ordinary choreography in that scheme.
- **Ack ownership**: `apply_avatar_commands` owns all `avatar.*` acks (one-owner-per-command rule, src/ai.rs:88-92); `Reset` clears avatar state silently (reset's single ack stays with `apply_ai_commands`, src/ai.rs:234-236 precedent at src/ai.rs:606-618).

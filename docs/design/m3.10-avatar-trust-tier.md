# Trusted scene-level capability tier — implementation design (#23 §2, #18 §1)

All paths relative to `/Users/tannerjacobsen/Documents/Claude/ratty`.

## 0. Design stance in one paragraph

Authority in ratty already has exactly one honest shape: **capability = ingress principal × out-of-band grant**, decided at apply time, never claimed in-band (`src/runtime.rs:38-43`). This design does not invent a second shape. It names the existing pattern in the type system — a `SceneCapability` enum and one total, exhaustive derivation function over `IngressSource` × `AppConfig` — so that every scene-level grant (avatar scene control today, `allow_scene_ambient` retroactively, future ones) flows through a single audited spine. It does **not** pretend ratty can distinguish two writers on one PTY: today the derivation has one arm (`Local`), so a grant is process-wide across every PTY writer, exactly as `allow_scene_ambient` already is (`src/config.rs:445-449`). The type-system payoff is forward-looking and real: the derivation match is exhaustive with no wildcard, so adding an authenticated `IngressSource` variant **fails to compile** until its scene-capability grants are explicitly decided.

## 1. Where trusted capability can actually come from today (the honesty clause)

Enumerated, closed set — everything else is the wire, and the wire can never self-escalate:

1. **Config file at process start.** Native: `AppConfig::load_from_path` (`src/config.rs:75-92`), called once in `main` (`src/main.rs:44`), selected by `-c/--config-file` (`src/cli.rs:20-21`). Fixed for the process lifetime — no hot reload (`src/config.rs:467-469`). This is the same trusted tier as `audio.allow_scene_ambient` (`src/config.rs:445-449`, enforced `src/sound.rs:592-602`) and `reactive.system_sensors` (`src/config.rs:473-477`, seeded `src/reactive.rs:1000-1024`).
2. **The wasm embedder.** On the site, config TOML is supplied by the embedding page to `start(canvas_selector, config_toml)` (`src/web.rs:315-322`). The page owns the process, so the page **is** the trusted tier on wasm — same key, same schema, first-class parity.
3. **Direct Rust API calls** (ratty's own UI/keyboard/controller code). These never travel the `AiCommand` stream and never synthesize one — an internal act is the terminal itself, not a principal, so it forges no `IngressSource`. Precedent: `MacroRegistry::insert_trusted` is "the trusted-tier entry point (config / CLI / UI / controller); the wire can never reach it" (`src/macros.rs:318-323`). The avatar organ exposes the same shape (see §6.3).
4. **Future authenticated `IngressSource` variants**, assigned out-of-band per the standing promise (`src/runtime.rs:41-43`). See §10.

Explicitly rejected sources:
- **No new CLI grant flag.** `--config-file` already selects the trusted document; a second writable path (`--allow-avatar-scene`) would be a second surface to audit for the same bit. One grant, one key.
- **No in-band grant, ever** — no `avatar.grant` command, no token that elevates. A stream cannot claim an identity (`src/runtime.rs:39-40`), so it cannot claim a tier.
- **No `IngressSource::Trusted` variant today.** Nothing can honestly construct it: internal acts bypass the wire entirely (path 3), and no authenticated transport exists. A variant nothing produces is a lie in the type system.

## 2. The capability type — new file `src/capability.rs`

New module, registered as `pub mod capability;` in `src/lib.rs` (insert after `pub mod cli;`, `src/lib.rs:11-12`, keeping the alphabetical order). Zero dependencies beyond `crate::config` and `crate::runtime`.

```rust
//! Scene-level capability derivation: the trusted tier of #23.
//!
//! A scene-level capability is authority over shared presentation state
//! that no agent namespace owns: the avatar's representation and global
//! visibility, other agents' queued speech, the scene ambient audio bed.
//! Ordinary wire agents never hold one implicitly — they submit attributed
//! speech and gestures inside their own namespace, and everything above
//! that tier answers `not-permitted`.
//!
//! Authority = ingress principal × out-of-band grant, decided at apply
//! time. The derivation below is pure and total over
//! ([`IngressSource`], [`AppConfig`]): nothing inside a byte stream
//! contributes to the answer, so the wire can never grant a capability to
//! itself. Grants come only from trusted config at load (the embedding
//! page's TOML on wasm) — the same tier as `audio.allow_scene_ambient`
//! and `reactive.system_sensors`.
//!
//! Honest limitation, stated plainly: [`IngressSource::Local`] is ONE
//! effective principal — a plain PTY cannot attribute bytes to individual
//! writer processes (see the `IngressSource` doc). A grant to `Local` is
//! therefore a grant to *every* process writing this terminal, exactly as
//! `allow_scene_ambient` is today. The match below is deliberately
//! exhaustive with no wildcard arm: when an authenticated transport adds
//! an `IngressSource` variant, this function stops compiling until that
//! transport's scene grants are decided explicitly, out-of-band.

use crate::config::AppConfig;
use crate::runtime::IngressSource;

/// A scene-level capability: one nameable unit of shared-scene authority.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum SceneCapability {
    /// Avatar scene control: change the avatar asset/representation
    /// (`avatar.set`), hide/show it globally (`avatar.hide`/`avatar.show`),
    /// clear another agent's queued speech, or cancel the whole speech
    /// queue (`avatar.speech.clear` beyond the caller's own entry).
    AvatarScene,
    /// Drive the scene ambient audio bed (`sound.ambient.set`). The grant
    /// bit lives at `[audio] allow_scene_ambient`, unchanged; this variant
    /// routes it through the one capability spine (see the module doc).
    SceneAmbient,
}

impl SceneCapability {
    /// Whether trusted config grants this capability to `source`.
    ///
    /// Pure derivation; call it at decision time, next to the ownership
    /// checks. `AppConfig` is loaded once at startup and is wire-immutable,
    /// so within a process the answer never changes.
    pub fn granted_to(self, source: IngressSource, config: &AppConfig) -> bool {
        match source {
            IngressSource::Local => match self {
                SceneCapability::AvatarScene => config.trust.local.avatar_scene,
                SceneCapability::SceneAmbient => config.audio.allow_scene_ambient,
            },
        }
    }
}
```

Why a derivation and not a stored `Capabilities` struct/resource: config is process-lifetime-constant (`src/config.rs:467-469`) and check sites already hold `Res<AppConfig>` (`src/sound.rs:446`, `src/ai.rs:317`), so a cached snapshot would be a second copy of the same truth that could drift. Why not attach to `CommandOrigin`: origin is explicitly causal, not authority (`src/ai.rs:51-54`); a rule- or macro-injected command runs under its owner's `source`, and the capability must follow that same `source` — which it does automatically, because macro playback re-injects under `playback.source` (`src/macros.rs:824-850`) and rule fires under the rule owner's `source` (`src/reactive.rs:1190-1197`). One enforcement point at apply time covers every path (wire, macro, bookmark, rule) with no per-path special cases.

## 3. Config surface — exact TOML and types

### TOML

```rust
/// Scene-level capability grants: the trusted tier of #23.
///
/// Everything here is config-only — no wire command can write it, and
/// there is no hot reload, so grants are fixed for the process lifetime.
/// Keyed by ingress principal: `[trust.local]` is the only principal that
/// exists today (see [`crate::runtime::IngressSource`]); authenticated
/// transports get their own tables when they land, out-of-band.
#[derive(Debug, Clone, Deserialize, Default)]
#[serde(default)]
pub struct TrustConfig {
    /// Grants for the local ingress principal: the spawned PTY on native
    /// builds, the embedding page's virtual channel on wasm.
    pub local: LocalTrustConfig,
}

/// Scene-capability grants for [`crate::runtime::IngressSource::Local`].
///
/// One PTY is one principal: a grant here reaches every process writing
/// the terminal — ratty cannot split it finer, and does not pretend to.
#[derive(Debug, Clone, Deserialize)]
#[serde(default)]
pub struct LocalTrustConfig {
    /// Grants avatar scene control (`avatar.set`/`show`/`hide`, clearing
    /// other agents' speech, cancelling the speech queue). Default true:
    /// a single-tenant session directs its own scene, mirroring
    /// `[audio] allow_scene_ambient`; multi-writer operators revoke it.
    pub avatar_scene: bool,
}

impl Default for LocalTrustConfig {
    fn default() -> Self {
        Self { avatar_scene: true }
    }
}
```

### `allow_scene_ambient`: expressed, not moved — justification

The task allows either. Decision: **the key stays at `[audio] allow_scene_ambient`** (`src/config.rs:449`); the capability spine reads it via `SceneCapability::SceneAmbient` (§2). Moving it (or aliasing it into `[trust.local]`) would create either a breaking config change or two keys for one grant with a conflict-resolution rule — a divergence surface with zero behavior gained. What the goal actually requires is that the boolean be *expressible* in the model, and it is: `sound.rs`'s check site converts to the spine (§6.2) with byte-identical behavior. The doc comment on `AudioConfig` gains one sentence pointing at `SceneCapability::SceneAmbient` as the canonical read path. When per-transport grants land, the derivation match is the single place that decides how the legacy key maps onto new principals.

## 4. Wire grammar additions (OSC 777, `ratty:` namespace)

The avatar family already parses: `avatar.set;model=&position=`, `avatar.gesture;gesture=`, `avatar.speak;text=`, `avatar.hide` (`src/osc.rs:426-445`, parse arms `src/osc.rs:873-884`); today all four fall into the `apply_ai_commands` catch-all and reject `unsupported` (`src/ai.rs:289-300`). The locked goal's capability split needs two additions:

```
avatar.show                          — show a hidden avatar without changing its representation
avatar.speech.clear                  — clear the caller's own pending utterance
avatar.speech.clear;ns=<n>           — clear namespace <n>'s pending utterance
avatar.speech.clear;scope=all        — cancel the whole queue, incl. the active utterance
```

Parse rules (matching the closed-vocabulary style of `macro.record;mode=`, `src/osc.rs:887-898`): `ns=` and `scope=` are mutually exclusive — both present fails the parse (`None`, which the ingress layer already turns into a `bad-command` error ack for `tok=` carriers, `src/osc.rs:641-653`); `scope=` accepts only `all`; `ns=` must parse as `u8`. New variants in `RattyAiCommand` beside the existing avatar block (`src/osc.rs:426-445`):

```rust
    /// Show a hidden avatar without changing its representation
    /// (`avatar.show`). Scene-global: requires the avatar-scene capability.
    AvatarShow,
    /// Clear queued avatar speech (`avatar.speech.clear`).
    AvatarSpeechClear {
        /// The clear scope. `Own` is ownership-scoped (ordinary tier);
        /// the other scopes are scene-global and require the avatar-scene
        /// capability, checked at apply time.
        scope: SpeechClearScope,
    },
```

```rust
/// The scope of an `avatar.speech.clear`.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum SpeechClearScope {
    /// The caller's own pending utterance (no `ns=`/`scope=`).
    Own,
    /// One namespace's pending utterance (`ns=<n>`). Equal to the
    /// caller's own namespace, this is ownership-scoped like `Own`;
    /// any other namespace is scene-global.
    Namespace(u8),
    /// The whole queue plus the active utterance (`scope=all`).
    All,
}
```

`avatar.set;model=` remains an **immutable embedded-registry ID only** (#12): resolution against the embedded avatar registry at apply time, `bad-asset` otherwise — the same rule as `object.add` (`src/ai.rs:12-15`) and the same reason `macro.export`/`macro.run` reject filesystem paths (`src/macros.rs:781-798`, `src/query.rs:123-126`). Note the existing parse default `model = "ai-helper.glb"` (`src/osc.rs:875`) is only a wire default; the registry decides what exists.

### Classification predicates (`src/osc.rs`)

Privileged set — extend `is_scene_global()` (`src/osc.rs:629-638`). This automatically propagates to macro privileged classification at capture (`src/macros.rs:498-500`), sealing at finalize (`src/macros.rs:524-532`), and the exclusive scene lock at play (`src/macros.rs:598-610`) — exactly the #16 clause:

```rust
    pub fn is_scene_global(&self) -> bool {
        match self {
            Self::SetMode { .. } | Self::SetWarp { .. } | Self::Reset => true,
            // Avatar scene control (#23): representation, global
            // visibility, and cross-agent queue authority are shared
            // scene state; a recording containing one is privileged.
            Self::AvatarSet { .. } | Self::AvatarShow | Self::AvatarHide => true,
            // Clearing one's own utterance is ownership-scoped; any wider
            // scope is scene-global. (Arg-dependent classification has
            // precedent: rule-safe `object.update` keys on x/y.)
            Self::AvatarSpeechClear { scope } => !matches!(scope, SpeechClearScope::Own),
            _ => false,
        }
    }
```

Note the deliberate conservatism baked into `Namespace(n)`: at classification time the caller is unknown, so `ns=<any>` classifies privileged even when `n` later turns out to be the caller's own namespace. A macro author who wants an unprivileged recording uses the bare form. Documented on the variant.

Rule allowlist (#21) — **zero code change required**: `is_rule_safe_action()` is default-deny (`_ => false`, `src/osc.rs:614-627`), so every avatar command (including speak/gesture) is excluded from `rule.set` validation (`src/reactive.rs:454-512`) and from rule-fired `macro.play` (fire-time re-check `src/macros.rs:588-597`; recompute on trusted promotion `src/macros.rs:343-346`). v1 keeps even `avatar.gesture` out of the allowlist — it is presence-like and could be admitted later as a deliberate, separate decision; admitting it now is scope creep on a locked list. Tests pin the exclusion (§9).

`is_control_plane()` (`src/osc.rs:600-602`) is untouched: avatar commands are choreography (recordable), not control-plane.

## 5. The check-site contract

### 5.1 Avatar applier (lands with the avatar organ, new file `src/avatar.rs`)

The organ itself (queue mechanics, rendering) is the sibling design; this design fixes its authority contract. Signature in the house applier shape (`src/sound.rs:443-450` is the model):

```rust
/// Applies queued `avatar.*` commands: the decision layer. Owns the ack
/// for every avatar command (one-owner invariant).
pub fn apply_avatar_commands(
    mut commands: MessageReader<AiCommand>,
    mut state: ResMut<AvatarState>,
    app_config: Res<AppConfig>,
    mut acks: MessageWriter<AckOutcome>,
    mut diagnostics: ResMut<AiDiagnostics>,
) {
    for AiCommand { source, ack_token, command, .. } in commands.read() {
        // reject! macro exactly as src/sound.rs:467-481.
        // The scene-capability gate, mirroring src/sound.rs:592-602:
        macro_rules! require_scene {
            ($action:literal) => {
                if !SceneCapability::AvatarScene.granted_to(*source, &app_config) {
                    reject!(
                        $action,
                        codes::NOT_PERMITTED,
                        "avatar scene control requires the avatar-scene \
                         capability ([trust.local] avatar_scene); ordinary \
                         agents may speak and gesture only"
                    );
                    continue;
                }
            };
        }
        match command {
            RattyAiCommand::AvatarSet { .. } => { require_scene!("avatar.set"); /* … */ }
            RattyAiCommand::AvatarShow => { require_scene!("avatar.show"); /* … */ }
            RattyAiCommand::AvatarHide => { require_scene!("avatar.hide"); /* … */ }
            RattyAiCommand::AvatarSpeechClear { scope } => {
                // Ownership scope first (#12/#16 spine): Own, and
                // Namespace(n) where n == source.namespace(), are the
                // caller's property. Everything wider is scene-global.
                let own = matches!(scope, SpeechClearScope::Own)
                    || matches!(scope, SpeechClearScope::Namespace(n) if *n == source.namespace());
                if !own { require_scene!("avatar.speech.clear"); }
                /* … */
            }
            RattyAiCommand::AvatarSpeak { text } => {
                // Ordinary tier: attribution is the ingress-derived
                // namespace, never anything in-band.
                /* state.enqueue(source.namespace(), text) → per-agent
                   single pending slot; over-slot rejects codes::BUSY */
            }
            RattyAiCommand::AvatarGesture { .. } => { /* ordinary tier, allowed-gesture registry check */ }
            RattyAiCommand::Reset => { /* clear queue + hide, silently; reset's ack belongs to apply_ai_commands (src/ai.rs:227-237) */ }
            _ => {}
        }
    }
}
```

Enforcement is **only** here, at apply time. That single choke point covers wire, macro-injected, bookmark, and rule paths identically because injected commands carry their owner's `source` (§2). A capability-lacking caller who plays a (privileged) macro containing `avatar.set` gets: the scene-lock discipline at play (`src/macros.rs:598-610`), then a per-step `not-permitted` rejection at apply — token-less (injected steps never carry `tok=`, `src/ai.rs:86-92`), so it lands as a `warn!` plus a `state.errors` ring record, which is the established explicit-not-silent posture for mid-playback step failures. No play-time capability pre-check: `privileged` is a content classification (mode/warp/reset need no capability), so a pre-check would either lie or require a second per-macro capability ledger — deferred until a real need appears.

## 6. NotAuthorized ack path

The locked goal's "NotAuthorized" is ratty's existing `codes::NOT_PERMITTED` (`"not-permitted"`, `src/query.rs:111-113`), whose doc comment already states this exact semantics: "The caller's ingress tier does not carry the required capability." No new code — a parallel `not-authorized` code would be a synonym and a wire-compat hazard. Path per rejection: `warn!` + `crate::query_channel::reject` (`src/query_channel.rs:232-250`) → caller-namespace `state.errors` ring + `ok=0;code=not-permitted` ack for `tok=` carriers, identical to the ambient precedent (`src/sound.rs:594-601`) and the #21 origin guard (`src/reactive.rs:1059-1076`).

Appended keys (append-only contract, `src/query_channel.rs:472`):

```rust
        // tier carries, derived from trusted config — discoverable before
        // attempting, never a promise of anything else.
        "trust": {
            "avatar_scene": SceneCapability::AvatarScene.granted_to(source, ctx.config),
```

- **`state.avatar`** (new op, added to `SUPPORTED_OPS`, `src/query_channel.rs:55-69`) follows the locked three-tier read scope (`src/query_channel.rs:11-23`): tier 1 — scene-public avatar state (visible?, model registry ID, position, the *currently speaking* namespace and text: it is on screen, hence public render projection); tier 2 — the caller's own pending utterance in full; tier 3 — for other namespaces, `{ns, queued: true}` only, never unspoken text. Capability holders get **no extra read scope**: visibility grants observation, not control (`src/query_channel.rs:18-20`), and symmetric control (cancel-all) needs no extra reads. That is "query authorization follows the caller's current capabilities and ownership scope" satisfied the way #12/#16 satisfy it — ownership widens *writes*, tiers bound *reads*, and `caps` truthfully reports the caller's tier.

## 11. Migration path when an authenticated transport lands

1. New variant, e.g. `IngressSource::Relay { peer: RelayPeerId }` (`src/runtime.rs:44-50`), namespace assigned in `namespace()` (`src/runtime.rs:52-59`) — the standing promise (`src/runtime.rs:41-43`).
2. `SceneCapability::granted_to`'s exhaustive match **stops compiling** — the compiler forces a per-transport grants decision. This is the type-system expression of the tier: forgetting is impossible.
3. Config grows `[trust.<transport>]` tables beside `[trust.local]` (`TrustConfig` gains fields; per-peer grants may instead arrive in the transport's out-of-band handshake — the derivation is the single place that arbitrates).
4. `SceneAmbient` for new transports is decided in the same match; the legacy `[audio]` key remains the `Local` arm's truth. Per-agent fairness/attribution machinery (per-namespace queue slots, rings) becomes real automatically — it is already namespace-keyed (§7, `src/query_channel.rs:148-151`).
5. Reply routing already refuses cross-source broadcast (`src/query_channel.rs:393-397`), so acks/queries stay per-principal with no extra work.

## 12. Test story

Unit (`src/capability.rs` `#[cfg(test)]`):
- `Local` × each capability × grant on/off — derivation truth table.
- `avatar_scene` default is `true`; `[trust.local] avatar_scene = false` parses via `AppConfig::from_toml_str` (`src/config.rs:102-104`); absent `[trust]` section defaults cleanly.

Applier integration (house pattern: full-app tests as in `src/reactive.rs:1972+`, `src/query_channel.rs:1112+`):
- grant revoked: `avatar.set`/`show`/`hide`/`speech.clear;scope=all`/`speech.clear;ns=1` each ack `ok=0;code=not-permitted` and land in `state.errors`; `avatar.speak`, `avatar.gesture`, bare `speech.clear`, and `speech.clear;ns=0` (own namespace) still commit.
- grant present: all six commit.
- attribution: a spoken utterance projects the ingress namespace (0), regardless of any in-band claim.
- one-owner: with the new no-op arms, no avatar command is double-acked by `apply_ai_commands`.

Classification (#16/#21):
- a recording containing `avatar.set` finalizes `privileged` and requires the scene lock at play (`src/macros.rs:598-610`); one containing only `speak`+`gesture` does not.
- `avatar.speech.clear;ns=` classifies privileged even for the recorder's own namespace (documented conservatism).
- every avatar command is non-rule-safe: `rule.set;do=avatar.speak…` rejects `not-permitted` (`src/reactive.rs:504-511`); a rule-origin `macro.play` of a macro containing any avatar step rejects at fire time (`src/macros.rs:588-597`); `insert_trusted` recomputes `rule_safe=false` (`src/macros.rs:343-346`).
- macro playback by a grant-less caller: privileged steps produce per-step `not-permitted` diagnostics, playback continues (explicit, not silent).

Sound migration: the existing ambient-gate tests pass unmodified after §5.2 — the expressiveness proof.

Query: `caps.trust` reflects config truthfully both ways; `state.avatar` hides other namespaces' unspoken text.

Compile-time: the no-wildcard match **is** the test that future `IngressSource` variants cannot skip the grants decision (assert via a doc note; CI's `clippy -D warnings` + `#![warn(missing_docs)]` (`src/lib.rs:6`) already gate doc coverage).

## 1. Mascot asset decision

There is no `ai-helper.glb`; the current parse default (`p.string_or("model", "ai-helper.glb")`, `src/osc.rs:875`) references a nonexistent asset and must change. Measured facts about the two embedded GLB candidates (parsed from the GLB containers directly):

| | SpinyMouse.glb | Ferris.glb |
|---|---|---|
| Packaged bytes | 1,684,108 (80.3% of 2 MiB cap) | 9,448 |
| Triangles | 818 | 274 |
| Materials | 1 | 4 |
| Images | 1 × PNG 2048×2048 (stored 1,623,351 B; decoded RGBA8 16,777,216 B) | 0 |
| Animations / skins | 0 / 0 | 0 / 0 |
| `extensionsRequired` | `[]` | `[]` |
| External URIs (buffers/images) | none — self-contained | none |
| BIN chunk | 1,681,956 B | 6,036 B |

**Decision: `mascot` → `SpinyMouse.glb`.**
- It is the project's visual identity (the spiny-mouse family: `CairoSpinyMouse.obj` is the default config cursor, `src/config.rs:563`; `SkateMouse.stl` alongside).
- It is *already embedded in every binary and the wasm bundle* (`src/model.rs:18-20`), so designating it adds **zero** bytes anywhere. Ferris is Rust's mascot, not ratty's.
- It fits the locked ≤2 MiB packaged cap with 19.7% headroom, and is genuinely low-poly (818 triangles).
- Commissioning a new asset is **deferred, justified**: the locked goal requires ONE validated GLB under budget, which SpinyMouse satisfies today. The registry ID (`mascot`) is a semantic name whose backing file is terminal-side detail the wire never sees (the sound organ's exact precedent, `src/sound.rs:94-97`), so a commissioned model later is a registry-row change, not a wire/protocol change.
- **Honest curation note (non-blocking follow-up)**: the 2048×2048 PNG is 96% of the file and ~91% of the decoded-runtime estimate. Re-exporting with a 1024×1024 texture would cut decoded texture memory 16 MiB → 4 MiB and the file to roughly 500 KB. The caps below are set so today's asset passes; tightening them after re-export is a constants change.

## 2. Registry surface

Two-layer split, byte-for-byte the sound organ's pattern (`osc::SOUND_KINDS` at `src/osc.rs:110` shared with the wire/CLI; `sound::SOUND_REGISTRY` at `src/sound.rs:98-134` terminal-side; lockstep pinned by test `src/sound.rs:1135-1140`).

**Wire-shared vocabulary — `src/osc.rs`, next to `SOUND_KINDS` (~line 110):**

```rust
/// The shared wire vocabulary of avatar model registry ids (#23 §3).
/// Immutable and append-only: an id, once shipped, never changes meaning
/// or disappears. Wire commands reference these ids only — never file
/// names, paths, or URLs (#12). Which embedded asset backs an id is
/// terminal-side detail the wire never sees (see
/// `crate::avatar::AVATAR_REGISTRY`; a test pins the lockstep).
pub const AVATAR_MODELS: &[&str] = &["mascot"];

/// The closed vocabulary of avatar screen anchors. Append-only like
/// `AVATAR_MODELS`; an unknown anchor rejects with `unknown-anchor`.
pub const AVATAR_ANCHORS: &[&str] =
    &["top-left", "top-right", "bottom-left", "bottom-right"];
```

**Terminal-side registry — new `src/avatar.rs`:**

```rust
/// One entry of the terminal-side avatar model registry: how an immutable
/// wire registry id resolves to an embedded asset and its presentation
/// normalization. Ids must stay in lockstep with
/// [`crate::osc::AVATAR_MODELS`] (a test pins this); files and scales are
/// terminal-side detail the wire never sees.
#[derive(Debug, Clone, Copy)]
pub struct AvatarModelSpec {
    /// The canonical registry id (matches `AVATAR_MODELS`).
    pub id: &'static str,
    /// Embedded asset file name under `assets/objects/` (never a path).
    pub file: &'static str,
    /// Uniform display scale applied to the spawned scene root.
    pub scale: f32,
}

/// The curated avatar registry. M3 ships exactly one validated model
/// (#23 §3); rows are append-only.
pub const AVATAR_REGISTRY: &[AvatarModelSpec] = &[AvatarModelSpec {
    id: "mascot",
    file: "SpinyMouse.glb",
    scale: 1.0,
}];

/// Looks up the registry entry for an id, or `None` when unregistered.
pub fn avatar_model_spec(id: &str) -> Option<&'static AvatarModelSpec> {
    AVATAR_REGISTRY.iter().find(|spec| spec.id == id)
}
```

**Why reuse `EmbeddedObjects` instead of a second RustEmbed folder:** `SpinyMouse.glb` is already a legitimate `object.add path=` target and a transmission asset; a second folder would either duplicate 1.68 MB in the binary or break the existing wire name. The #12 registry-ID-only rule is enforced by the *lookup path* (wire → `AVATAR_MODELS` id → `avatar_model_spec` → embedded file), not by folder layout — identical to how `sound.play kind=chime` resolves through `SOUND_REGISTRY` to `chime.ogg` without the wire ever naming the file (`src/sound.rs:136-158`).

## 3. Wire grammar and ack error codes

### 3.1 Grammar change (`src/osc.rs:874-877`)

```rust
// Avatar (#23). `model` and `anchor` are closed registry vocabularies
// validated at apply time so unknown names get explicit ack codes
// (unknown-model / unknown-anchor), not a generic bad-command.
"avatar.set" => RattyAiCommand::AvatarSet {
    model: p.string_or("model", "mascot"),
    anchor: p.string_or("anchor", "top-right"),
},
```

- The enum field and wire key rename `position` → `anchor` (`src/osc.rs:428-433`) to match the locked goal's vocabulary ("unknown model or **anchor** names"). This breaks no caller: every `avatar.*` command today falls into the `apply_ai_commands` catch-all and rejects `unsupported` (`src/ai.rs:289-300`), so there are no working callers by definition; no shipped transmission uses `avatar.*` (grepped). Parse tests at `src/osc.rs:1479-1482` update accordingly.
- The default model changes `"ai-helper.glb"` → `"mascot"` — the old default names an asset that has never existed.
- `avatar.gesture` / `avatar.speak` / `avatar.hide` grammar is untouched.
- Validation stays at **apply** time (not parse) deliberately: parse-`None` produces the generic `bad-command` ack, while the locked goal demands *explicit* unknown-name errors. The parse-permissive/apply-strict split is the same one `object.add` uses for asset names (`src/ai.rs:429-438`).

### 3.2 New ack codes (`src/query.rs`, `codes` module, append after `STALE_SEQ`, line 135)

```rust
/// An avatar model id not in the registry (`AVATAR_MODELS`); wire
/// commands reference immutable registry ids only, never paths (#23 §3).
pub const UNKNOWN_MODEL: &str = "unknown-model";
/// An avatar anchor name not in the anchor vocabulary (`AVATAR_ANCHORS`).
pub const UNKNOWN_ANCHOR: &str = "unknown-anchor";
```

Codes are append-only per the module contract (`src/query.rs:53-56`). Existing codes are wrong fits: `BAD_ASSET` means "not a loadable embedded asset (filename)" (`src/query.rs:89-90`) and the avatar wire never carries filenames; `NO_ANCHOR` means "object scrolled away" (`src/query.rs:79-80`).

### 3.3 Apply-path rejections (in the new organ, §6)

Mirroring the `reject!` macro pattern of `apply_ai_object_commands` (`src/ai.rs:335-347`), with `warn!` beside every reject per house style:

- unknown model → `reject!("avatar.set", codes::UNKNOWN_MODEL, "model '{model}' is not a registered avatar model (mascot)")`
- unknown anchor → `reject!("avatar.set", codes::UNKNOWN_ANCHOR, "anchor '{anchor}' is not a known anchor (top-left, top-right, bottom-left, bottom-right)")`
- happy path → `ack_commit` (`src/query_channel.rs:194-207`); rejections also land in the caller's `state.errors` ring via `reject` (`src/query_channel.rs:232-250`).

## 4. build.rs enforcement

### 4.1 What is honestly statically verifiable (and what is not)

Verifiable from the GLB container alone (no GPU, no decoder), all confirmed against `gltf-1.4.1/src/binary.rs:80-140` and `gltf-json-1.4.1`:
- container integrity: magic `glTF`, version == 2, declared length == file length, JSON-first chunk walk with 4-byte alignment;
- **triangles**: per `meshes[].primitives[]`, `accessors[indices].count / 3` (or `POSITION` count when non-indexed; mode defaults to 4 = TRIANGLES — any other mode fails the audit);
- **materials**: `materials.len()`; **images**: `images.len()`;
- **texture dimensions**: each image's `bufferView` slice of the BIN chunk; PNG mandates IHDR first, so width/height are big-endian u32 at bytes 16/20 — no decoder needed;
- **mimeType == `image/png`** — mandatory because ratty compiles only the `png` bevy image format (`Cargo.toml:61`); a JPEG texture would fail at *runtime* on both targets, so the build must reject it;
- **`extensionsRequired` empty** — this is the "Draco/meshopt verified, not assumed" clause. Verified: bevy_gltf 0.19 enables only `KHR_lights_punctual`, `KHR_materials_{transmission,ior,volume,unlit,emissive_strength}`, `KHR_texture_transform` (+extras/extensions/names/utils) (`bevy_gltf-0.19.0/Cargo.toml:116-129`); `ENABLED_EXTENSIONS` contains no draco/meshopt entry (`gltf-json-1.4.1/src/extensions/mod.rs:40-63`); bevy_gltf loads with `validate: true` by default (`bevy_gltf-0.19.0/src/loader/mod.rs:231`), so a Draco GLB *already* fails at runtime — the build check moves that failure to compile time with an actionable message;
- **self-containment**: any `buffers[]`/`images[]` entry carrying a `uri` field fails (external `.bin`/image bytes cannot be budget-audited or embedded);
- **decoded-runtime estimate**: BIN-chunk bytes (geometry is stored raw once compression extensions are rejected) + Σ(W×H×4) decoded RGBA8 texture bytes — the same rgba8 normalization ratty already applies to cursor textures (`src/model.rs:258-260`).

**Not statically verifiable — documented in the auditor's doc comment, no pretend caps**: actual GPU memory (device `CompressedImageFormatSupport` is resolved at `GltfPlugin::finish`, `bevy_gltf-0.19.0/src/lib.rs:281-290`), mipmap allocation, animation runtime cost, post-spawn entity/material dedup, and whether `Scene(0)` is the semantically intended scene.

### 4.2 Constants (all pass today's shipped assets; measured margins in §1)

```rust
/// Per-asset byte budget for embedded objects under `assets/objects/`
/// (the locked #23 §3 cap: ≤ 2 MiB packaged). SpinyMouse.glb, the avatar
/// mascot, is 1,684,108 bytes — 80% of this.
const OBJECT_ASSET_BUDGET_BYTES: u64 = 2 * 1024 * 1024;
/// Whole-package byte budget for `assets/objects/` as a set (all of it is
/// embedded into every binary and the wasm bundle via `EmbeddedObjects`).
/// Currently 1,932,883 bytes.
const OBJECT_PACKAGE_BUDGET_BYTES: u64 = 4 * 1024 * 1024;
/// Triangle cap per GLB ("low-poly" made falsifiable). Shipped: 818 / 274.
const GLB_MAX_TRIANGLES: u64 = 5_000;
/// Material cap per GLB. Shipped: 1 / 4.
const GLB_MAX_MATERIALS: usize = 8;
/// Embedded image cap per GLB; every image must be PNG (the only compiled
/// image format, Cargo.toml) and at most this many pixels per side.
const GLB_MAX_IMAGES: usize = 4;
const GLB_MAX_TEXTURE_DIM: u32 = 2048;
/// Decoded-runtime estimate cap: BIN chunk bytes + Σ(W×H×4) RGBA8 texture
/// bytes. An estimate of CPU-side decode + GPU upload, NOT device truth
/// (see doc comment). SpinyMouse.glb: 18,459,172 bytes — 88% of this.
const GLB_MAX_DECODED_BYTES: u64 = 20 * 1024 * 1024;
```

The audit runs over **every** `.glb` under `assets/objects/` (both shipped GLBs pass), because every one of them rides every binary and is wire-loadable via `object.add`; the avatar's asset is therefore covered a fortiori, and build.rs needs no knowledge of the Rust-side registry (that lockstep is a unit test, §9). A `.gltf` file appearing in `assets/objects/` fails the build outright ("embedded scene assets must be self-contained .glb").

## 5. wasm story — the real fix (no "unsupported" answer needed)

### 5.1 Mechanism (every claim source-verified)

Bevy's `AssetPlugin::build` unconditionally creates an `EmbeddedAssetRegistry`, registers it as the `embedded` source backed by a `MemoryAssetReader`, and inserts the registry as a resource (`bevy_asset-0.19.0/src/lib.rs:350-363`, `app.insert_resource(embedded)` at `:414`; source name `EMBEDDED = "embedded"`, `io/embedded/mod.rs:24`). The registry's `Dir` is `Arc`-shared with the already-built reader (`register_source` clones the `Dir`, `io/embedded/mod.rs:93-105`; `Dir(Arc<RwLock<…>>)` with `Default + Clone`, `io/memory.rs:30-31`), so **bytes inserted after plugin build are visible to the reader**. `insert_asset(full_path: PathBuf, asset_path: &Path, value: impl Into<Value>)` accepts `Vec<u8>` or `&'static [u8]` (`io/embedded/mod.rs:43-45`; `From` impls `io/memory.rs:306-316`). The whole module has no target cfg (`io/mod.rs:10` — `pub mod embedded;` unconditional; `pub mod memory;` at `:13`), and `"embedded://objects/x.glb"` parses as a sourced asset path (`bevy_asset-0.19.0/src/path.rs:104-133`). bevy_gltf itself parses from in-memory bytes delivered by any reader (`gltf::Gltf::from_slice`, `bevy_gltf-0.19.0/src/loader/mod.rs:210-250`; `reader.read_to_end` at `:1173`) and compiles cleanly on wasm (the only real target cfg is the sequential-texture branch, `:618, :636-640`); ratty's base bevy features already include `bevy_gltf`, `gltf_animation`, `bevy_scene`, `png` on **all** targets (`Cargo.toml:46-65`).

### 5.2 Changes

**(a) Seeder — `src/model.rs`, new public fn:**

```rust
/// Seeds every embedded `.glb`/`.gltf` object into Bevy's built-in
/// `embedded://` in-memory asset source, so glTF scenes load identically
/// on native and wasm — no filesystem staging, no web bail. Must run
/// after `AssetPlugin` inserts the `EmbeddedAssetRegistry` resource and
/// before the first embedded scene load; `TerminalPlugin::build`
/// satisfies both (both entry points add it after `DefaultPlugins`:
/// main.rs:73-106, web.rs:347-375).
///
/// # Panics
///
/// Panics when the `EmbeddedAssetRegistry` resource is missing, i.e. the
/// plugin order contract above is broken — a startup wiring bug, never a
/// runtime condition.
pub fn seed_embedded_scene_assets(world: &mut World) {
    use bevy::asset::io::embedded::EmbeddedAssetRegistry;
    use std::borrow::Cow;
    let registry = world.resource::<EmbeddedAssetRegistry>();
    for name in EmbeddedObjects::iter() {
        let is_scene = std::path::Path::new(name.as_ref())
            .extension()
            .and_then(|ext| ext.to_str())
            .is_some_and(|ext| ext.eq_ignore_ascii_case("glb")
                || ext.eq_ignore_ascii_case("gltf"));
        if !is_scene {
            continue;
        }
        let file = EmbeddedObjects::get(&name).expect("iterated names resolve");
        let asset_path = std::path::PathBuf::from("objects").join(name.as_ref());
        match file.data {
            // Release builds embed statically: zero-copy insert.
            Cow::Borrowed(bytes) => registry.insert_asset(asset_path.clone(), &asset_path, bytes),
            Cow::Owned(bytes) => registry.insert_asset(asset_path.clone(), &asset_path, bytes),
        }
    }
}
```

Called from `TerminalPlugin::build` (`src/plugin.rs:41`), first statement: `crate::model::seed_embedded_scene_assets(app.world_mut());`. Plugin `build` runs synchronously at `add_plugins`, so the resource deterministically exists (DefaultPlugins added first at `src/main.rs:73-104` / `src/web.rs:347-374`) and seeding deterministically precedes `setup_scene`'s Startup cursor spawn — no system-ordering edge.

**(b) Loader — `src/model.rs:345-352` collapses to one cfg-free arm:**

```rust
"glb" | "gltf" => Ok((
    source,
    ObjectSource::Gltf(format!("embedded://objects/{file_name}")),

```

Also: the embedded-candidate GLB branch of native `load_object_source_with_options` (`src/model.rs:467-474`) returns the same `embedded://` path; the wasm `load_object_source_with_options` (`src/model.rs:365-394`) gains the matching `"glb" | "gltf"` arm; `embedded_object_loadable` drops its native-only glTF gate (`src/model.rs:299-302` — `matches!(extension.as_str(), "obj" | "stl" | "glb" | "gltf")`). Doc comments claiming "glTF is native-only / the web build cannot stage scene assets" are rewritten to state the new truth (`src/model.rs:280-283, 305-321, 317-321, 357-360`).

**(c) Consumers need zero changes.** `asset_server.load(GltfAssetLabel::Scene(0).from_asset(asset_path.clone()))` already takes the stored string (`src/systems.rs:1101-1116`, `src/model.rs:211-217`); the string now carries the `embedded://` source prefix.

## 0. Design summary

One sentence: a long-running command's **single** `t=r;kind=ack` reply carries its status as an `ok=1` qualifier `code=` (`started` / `queued` — the `deferred` precedent, `src/query.rs:103-106`, `protocols/query.md:77-81`) plus a structured `data=` payload holding the **execution handle**, **queue position**, and **estimated wait**; the handle is later inspected through the existing `state.executions` / `state.scene` query ops (widened, no new op), and completion is observed by polling — `t=e` stays reserved, nothing is ever pushed.

No new crates. No Bevy feature changes. No new query ops. One new module (`src/avatar.rs`), one new field on `AckOutcome`, two new wire actions (`avatar.stop`, `avatar.cancel`), four new append-only codes (`started`, `queued`, `agent-queue-full`, `text-too-long`).

## 1. Wire grammar additions

The reply grammar is **unchanged** — the locked #18 grammar already carries every field needed (`src/query.rs:386-408` emits `data=` after `kind=ack`; `parse_reply_body` decodes it unconditionally, `src/query.rs:428-464`; spec `protocols/query.md:37-40`):

```text
reply:  ESC ] 778 ; v=1 ; t=r ; id=<token> [; kind=ack] ; ok=1|0 [; code=<outcome>] [; data=<b64url-json>] ESC \
```

What changes is **semantics**, documented in `protocols/query.md` (amending the ack section at `protocols/query.md:56-81`):

- A long-running command's ack is still exactly one frame, emitted after admission is decided (`ok=0` + rejection code, or `ok=1`).
- On `ok=1` the qualifier `code=` is `started` (executing now) or `queued` (admitted to a queue) — new append-only codes beside `deferred`. Clients that ignore unknown success codes (already mandated, `protocols/query.md:78-81`) see a plain success.
- `data=` on the ack decodes to a flat JSON object (keys append-only, alphabetical under serde_json's default `BTreeMap`):
  - `"id"`: the execution handle (string, §3),
  - `"position"`: how many executions hold the resource before this one — `0` for `started`,
  - `"eta_ms"`: estimated wait in ms until this execution starts — `0` for `started`; **or** `"eta_frames"` for `macro.play;mode=instant`, whose bound is the shared per-frame budget (`MAX_PLAYBACK_COMMANDS_PER_FRAME` = 64, `src/macros.rs:105-109`) and where Bevy's `Time` promises no future frame duration at admission — an honest frames-not-seconds answer.
- `position`/`eta_ms` are **estimates pinned at admission**: cancellations shorten them, and round-robin admission by an agent earlier in the rotation can lengthen them. The live values are polled via `state.executions`. Documented, not hidden.
- **No completion event.** Same posture as `deferred`: "There is no later notification — clients poll" (`src/query.rs:103-106`). `t=e` remains reserved and unemitted (`src/query.rs:16-17`, `protocols/query.md:51-52`).

```rust
/// Writes the single ack for an admitted long-running operation (#18):
/// `ok=1`, a status qualifier code (`codes::STARTED` / `codes::QUEUED`),
/// and a structured `data=` payload carrying the execution handle, queue
/// position, and estimated wait. Exactly one ack per command, emitted at
/// admission — completion is observed by polling, never pushed (t=e
/// stays reserved).
pub(crate) fn ack_commit_long_running(
    acks: &mut MessageWriter<AckOutcome>,
    source: IngressSource,
    ack_token: &Option<String>,
    status: &'static str,
    payload: serde_json::Value,
) {
    if let Some(token) = ack_token {
        acks.write(AckOutcome {
            source,
            token: token.clone(),
            ok: true,
            code: Some(status),
            payload: Some(payload),
        });
    }
}
```

## 3. Execution handles — mint scheme, uniqueness, lifecycle

**Mint scheme.** Handles are minted by the session identity that already exists — `QuerySession` (`src/query_channel.rs:113-131`), whose nonce is random per process (`getrandom03`, `:133-137`), never accepted in-band, and exposed by `caps` as `session` (`:476`) so clients detect restarts. Extend it:

```rust
#[derive(Resource)]
pub struct QuerySession {
    nonce: u64,
    /// Monotone counter for execution handles minted this session.
    next_execution: u64,
}

impl QuerySession {
    pub fn nonce_hex(&self) -> String { format!("{:016x}", self.nonce) }   // existing

    /// Mints a session-unique execution handle: `<nonce-hex>-<seq>`.
    /// Handles use the b64url alphabet (hex, `-`, digits) so they ride
    /// wire payload values and JSON unescaped.
    pub fn mint_execution_id(&mut self) -> String {
        self.next_execution += 1;
        format!("{:016x}-{}", self.nonce, self.next_execution)
    }

    /// Whether `id` was minted by THIS session. A handle from a previous
    /// process fails here and answers `unknown-id` — explicit staleness,
    /// mirroring how session-scoped pagination cursors fail decode
    /// (`src/query_channel.rs:106-112`).
    pub fn owns_execution_id(&self, id: &str) -> bool {
        id.strip_prefix(&self.nonce_hex())
            .is_some_and(|rest| rest.starts_with('-'))
    }
}
```

- **Uniqueness across restart**: the 64-bit random nonce prefix makes cross-restart collision ≈2⁻⁶⁴; within a session the counter is monotone. Handle length ≤ 37 bytes.
- **Lifecycle**: a handle names **live execution state only** — an avatar utterance (active or queued) or an active macro playback. Completed/cancelled executions leave **no tombstone**: absence from `state.executions` (and from `state.scene.avatar.execution`) *is* the completion signal. This is the bounded-memory posture of every registry in the repo (cf. the diagnostics ring, `src/query_channel.rs:41-46`) and the `deferred` poll-don't-notify precedent (`src/query.rs:103-106`). Documented in `protocols/query.md` as: *"a handle not present in `state.executions` has finished or was cancelled; handles are never reused within a session."*
- **Expiry clocks**: avatar utterances expire by their pinned duration on `Res<Time>` (§5); macro playbacks clear when the last step emits (`src/macros.rs:851-861`); `reset` clears both (`src/macros.rs:636-640` and the new `AvatarState::reset`).
- **Relation to the macro executions registry**: there is no generic handle table today (`MacroRegistry.slots` is namespace-keyed, capacity one, `src/macros.rs:246-252,282-295`). This design deliberately does **not** build one: each organ keeps owning its execution state, handles are just strings minted from one source (`QuerySession`), and `state.executions` is the single merged projection (§6). A central table would duplicate ownership the organs already have and add a second lifecycle to keep consistent — rejected as surface without depth.

### 5.2 Types

```rust
/// One admitted utterance; everything here is pinned at admission.
#[derive(Debug, Clone)]
struct Utterance {
    /// Execution handle (`QuerySession::mint_execution_id`).
    id: String,
    /// Owning agent namespace.
    namespace: u8,
    /// The text. Projected only to its owner (`state.executions`); never
    /// to other agents (`state.scene` carries no text).
    text: String,
    /// Pinned display duration (750 ms – 15 s).
    duration: Duration,
}

#[derive(Debug)]
struct ActiveUtterance {
    utterance: Utterance,
    /// `Time::elapsed` when the utterance took the voice.
    started: Duration,
}

/// The avatar organ's state: visibility plus the fair bounded speech
/// queue (#23 §2). One active utterance globally; per-agent FIFO queues
/// under a numeric-order round-robin rotation.
#[derive(Resource, Default)]
pub struct AvatarState {
    /// Shown/hidden (`avatar.set` / `avatar.hide`). The renderer
    /// (#23 §1) consumes this; the queue is independent of it.
    visible: bool,
    /// Pinned embedded model + screen position from the last `avatar.set`.
    model: Option<String>,
    position: Option<String>,
    active: Option<ActiveUtterance>,
    /// Per-agent FIFO queues, each ≤ MAX_PENDING_UTTERANCES_PER_AGENT.
    /// VecDeque keeps FIFO-within-agent structural if the cap ever rises.
    queues: HashMap<u8, VecDeque<Utterance>>,
    /// Invariant: Σ queues[*].len(), ≤ MAX_PENDING_UTTERANCES_GLOBAL.
    pending_total: usize,
    /// The namespace whose utterance most recently took the voice — the
    /// round-robin rotation point (set at start, so a cancelled speaker
    /// still consumed its turn).
    last_served: Option<u8>,
}

pub enum SpeakAdmission {
    Started,
    Queued { position: usize, eta: Duration },
}

/// Wire code + human message, the `MacroReject` pattern (src/macros.rs:299).
```

### 5.3 Registry methods (exact semantics)

```rust
impl AvatarState {
    /// Admits one utterance. Check order: text-too-long → agent-queue-full
    /// → busy. Starts immediately (Started) iff no active utterance AND no
    /// pending utterance exists — a same-frame cancel never lets a new
    /// admission jump the queue. Sets last_served on immediate start.
    pub fn admit(&mut self, namespace: u8, id: String, text: String,
                 duration: Duration, now: Duration)
                 -> Result<SpeakAdmission, AvatarReject>;

    /// AvatarStopSpeaking: cancels the caller's active utterance if the
    /// caller is the current speaker, else the caller's queued utterance;
    /// `nothing-active` when neither exists. Promotion of the next speaker
    /// happens in drive_avatar_speech (≤ 1 frame later), never here.
    pub fn stop_speaking(&mut self, namespace: u8) -> Result<(), AvatarReject>;

    /// AvatarCancel { execution_id }: `unknown-id` when no live execution
    /// carries the handle (including handles minted by a previous session,
    /// pre-screened via QuerySession::owns_execution_id with an honest
    /// "handle is from a previous session" message); `not-owner` when it
    /// belongs to another namespace — an agent cancels only its own.
    pub fn cancel(&mut self, namespace: u8, execution_id: &str)
                  -> Result<(), AvatarReject>;

    /// Frame tick: expires the active utterance at its pinned duration,
    /// then promotes the round-robin-next pending utterance.
    pub fn tick(&mut self, now: Duration);

    /// Round-robin selection: pending namespaces in cyclic numeric (u8)
    /// order, starting strictly after last_served, wrapping.
    fn next_namespace(&self) -> Option<u8>;

    /// Queue position of `namespace`'s pending utterance: 1 + the number
    /// of pending utterances served before it in rotation order, + 1 if an
    /// active utterance exists. Position 0 means "speaking now".
    fn position_of(&self, namespace: u8) -> Option<usize>;

    /// Estimated wait: remaining(active) + Σ pinned durations of pending
    /// utterances ahead in rotation. Exact under no-cancellation and
    /// no-earlier-rotation-admission; an estimate otherwise (documented).
    fn eta_of(&self, namespace: u8, now: Duration) -> Option<Duration>;

    pub fn has_speech(&self) -> bool;        // run-condition
    pub fn queue_depth(&self) -> usize;      // pending_total
    pub fn public_scene(&self) -> serde_json::Value;              // §8
    pub fn execution_items(&self, namespace: u8, now: Duration)
                           -> Vec<serde_json::Value>;             // §6
    /// `reset` tap: clears active, queues, visibility, model. The reset
    /// ack belongs to apply_ai_commands (src/ai.rs:227-237), same as the
    /// macros tap (src/macros.rs:799-803).
    pub fn reset(&mut self);
}
```

**Fairness properties** (documented in `protocols/avatar.md`, testable): one active utterance globally; ≤ 4 pending globally; ≤ 1 pending per agent; FIFO within an agent (structural via `VecDeque`); round-robin across agents ⇒ an admitted utterance starts after at most `remaining(active) + 3 × MAX_UTTERANCE_MS` (≤ ~45 s) regardless of other agents' behavior. Note: global FIFO would *not* satisfy round-robin (an agent re-queueing right after speaking would starve later admitters); the rotation pointer is load-bearing.

**Note on today's ingress**: only `IngressSource::Local` (namespace 0) exists (`src/runtime.rs:45-57`), so multi-agent fairness is exercised by registry-level unit tests with explicit namespaces until a second ingress lands. The machinery is namespace-generic per the locked multi-agent goal — same stance as the per-namespace macro slots.

## 6. Status queries — widen `state.executions`, no new op

**No `SUPPORTED_OPS` change** (`src/query_channel.rs:55-69`) — the caps test (`:1151-1157`) is untouched. The locked "inspected later through explicit status queries" is satisfied by the two existing ops the goal itself names (`state.executions`, `state.scene`).

Answer arm (`src/query_channel.rs:448-451`) becomes:

```rust
"state.executions" => Ok(executions_state(ctx, source)),
```

with a merged projection in `query_channel.rs`:

```rust
/// `state.executions`: the caller's own executions — the macro slot (0 or
/// 1 items) plus the caller's avatar utterances (own active and own
/// queued). Executions are private per-agent: another agent's utterances
/// (and their text) are never projected here; the aggregate is in
/// `state.scene`. Absence of a previously-issued handle means finished
/// or cancelled — handles are live-state references, never tombstoned.
```
